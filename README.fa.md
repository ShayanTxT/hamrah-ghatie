# همراه قطعی 🟢🟡🔴

یک برنامهٔ **پرتابل ویندوزی** برای روزهایی که اینترنت ایران قطع میشود یا فقط
«اینترنت ملی» میماند. بعد از یکبار راهاندازی (وقتی نت هست)، **۱۰۰٪ بدون
اینترنت** کار میکند: وضعیت اتصال، کیف آمادگی، کتابخانهٔ آفلاین، دستیار هوش
مصنوعی محلی و اشتراک فایل در شبکهٔ محلی.

- سیستمعامل هدف: ویندوز ۱۰/۱۱، ۶۴ بیتی
- رابط: کاملاً فارسی، راستبهچپ، تاریخ شمسی، فونت وزیرمتن **داخل برنامه**، حالت روشن/تیره
- نصب: **ندارد**. یک پوشه است که از روی فلش هم اجرا میشود.
- هیچ CDN، فونت آنلاین، API ابری، تلهٔمتری یا بررسی آپدیت خودکار وجود ندارد.

> ⚠️ **صداقت دربارهٔ تست (حتماً بخوانید):** محیط ساخت من لینوکس است. منطق
> برنامه (۵۵ تست خودکار)، رابط کاربری (بهصورت offscreen با همان PySide6)،
> خواندن یک فایل ZIM واقعی، انتقال فایل رمزنگاریشده بین دو گره روی TCP واقعی،
> و دانلود/ذخیرهٔ صفحه روی یک سرور HTTP محلی، همگی **واقعاً اجرا و تست
> شدهاند**. ولی **فایل exe ویندوزی را در این محیط نساختم و روی ویندوز اجرا
> نکردم**؛ `build.bat` و یک workflow آمادهٔ GitHub Actions روی `windows-latest`
> قرار دادهام تا همانجا ساخته شود. جزئیات کامل در بخش «چه چیزی تست شد».

## ۱. چرا Python 3.11 + PySide6؟

| معیار | نتیجه |
|---|---|
| پشتیبانی فارسی/RTL | Qt شکلدهی حروف عربی/فارسی را با HarfBuzz انجام میدهد و `setLayoutDirection(RightToLeft)` کل رابط را برمیگرداند. فونت را میتوان داخل باینری embed کرد. |
| حجم | خروجی PyInstallerِ onedir اندازهگیری شده **حدود ۲۵۰ مگابایت** (بدون مدل و ZIM و بدون بستهٔ اختیاری libzim). حدود نیمی از آن کتابخانههای Qt/ICU است. Tauri سبکتر است ولی باید FTS5، ZIM و رمزنگاری را از صفر بنویسیم. |
| رم | هستهٔ برنامه بدون Qt است؛ فقط هنگام باز بودن پنجره حدود ۱۰۰–۱۵۰ مگابایت رم میگیرد. مدل هوش مصنوعی فقط وقتی اجرا میشود که خودتان دکمه بزنید. |
| بستهبندی | `PyInstaller --onedir` یک پوشهٔ کامل میدهد که بدون نصب و بدون Python از پیشنصبشده اجرا میشود. |
| اعلان ویندوز | `QSystemTrayIcon` اعلان بومی ویندوز میدهد. |
| بقیه | SQLite FTS5 (جستجوی تماممتن فارسی)، `pypdf`، `cryptography`، `zstandard`، `psutil` — همگی کتابخانههای سبک و آفلاین. |

هسته (`hamrah/core`) **هیچ وابستهای به Qt ندارد** تا بشود آن را مستقل تست کرد؛
`hamrah/ui` فقط لایهٔ نمایش است.

├─ tests/                      # ۵۵ تست خودکار

├─ build.bat / hamrah-ghatie.spec

## ۳. راهاندازی اول

### الف) اجرای سریع از سورس (برای تست، روی ویندوز یا لینوکس)

```bat
:: ویندوز
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

```bash
# لینوکس/مک (فقط توسعه)
pip install -r requirements.txt
python3 run.py
```

### ب) ساخت نسخهٔ پرتابل ویندوزی (روی ویندوز ۱۰/۱۱ ۶۴بیتی)

1. Python **3.11 x64** نصب کنید (هنگام نصب `Add python.exe to PATH` را بزنید).
2. `build.bat` را اجرا کنید. این اسکریپت:
   - محیط مجازی میسازد و وابستگیها را نصب میکند،
   - تستها را اجرا میکند،
   - با PyInstaller پوشهٔ `dist\همراه قطعی\` را میسازد،
   - پوشهٔ `data` و فایلهای راهنما را کنار exe قرار میدهد،
   - یک ZIP برای ریختن روی فلش میسازد.
3. خروجی: `dist\همراه قطعی\HamrahGhatie.exe` ← دوبار کلیک کنید. نیازی به
   نصب، اینترنت یا Python روی مقصد نیست.

**بدون ویندوز؟** در GitHub، workflow «ساخت نسخهٔ پرتابل ویندوزی» را با
`Run workflow` اجرا کنید تا روی `windows-latest` ساخته شود و فایل ZIP را از
`Artifacts` بگیرید. (من اینجا نتوانستم exe را بسازم؛ صادقانه گفتم.)

> فونت وزیرمتن از قبل در `assets/fonts` قرار دارد و داخل بستهبندی کپی میشود.
> فایلهای `models/` و `library/zim/` **عمداً خالیاند** تا حجم برنامه کم بماند.

### اولین اجرا (وقتی هنوز اینترنت هست)

1. program را باز کنید؛ تب «تنظیمات» ← یک **کد جفتسازی ۶رقمی** وارد کنید
   (همین کد را روی کامپیوترهای دیگر هم بگذارید).
2. تب «کتابخانهٔ آفلاین» ← فایل `samples/wikipedia_climate_change_mini.zim`
   را وارد کنید تا مطمئن شوید خوانندهٔ ZIM کار میکند.
3. تب «دستیار آفلاین» ← فایل `llama-server.exe` و مدل GGUF را وارد کنید.
4. فایلهای ضروری را طبق بخش بعد دانلود کنید و **یکبار تست کنید**.

## ۴. قبل از قطعی چه فایلهایی دانلود کنم؟

همهٔ دانلودها **دستی و فقط در مرحلهٔ آمادهسازی** انجام میشوند. راحتترین راه:

```bat
python tools\prepare_downloads.py --list
python tools\prepare_downloads.py --minimal
:: یا دلخواه:
python tools\prepare_downloads.py --preset zim-fa-mini --preset model-balanced --preset llama-cuda
```

اسکریپت فایلها را در همان `data/` میریزد، دانلودها **قابلادامه**اند و بستههای
llama.cpp را خودش استخراج میکند. حجمها تقریبی و مربوط به نسخههای پینشدهٔ
زیر هستند (تاریخ نگارش: مهر/آبان ۱۴۰۵).

| فایل | حجم حدودی | کجا برود | توضیح |
|---|---:|---|---|
| `llama-b11901-bin-win-cpu-x64.zip` | ۳۰ مگ | `data/bin` | `llama-server.exe` نسخهٔ CPU — اگر GPU ندارید |
| `llama-b11901-bin-win-cuda-12.4-x64.zip` | ۲۵۰ مگ | `data/bin` | نسخهٔ CUDA برای کارت NVIDIA (پیشنهاد برای سیستم شما) |
| `cudart-llama-bin-win-cuda-12.4-x64.zip` | ۳۰۰ مگ | `data/bin` | کتابخانههای همراه نسخهٔ CUDA |
| `Qwen2.5-3B-Instruct-Q4_K_M.gguf` | **۱٫۹ گیگ** | `data/models` | مدل سبک، برای کامپیوتر متوسط ۸ گیگ رم |
| `Qwen2.5-7B-Instruct-Q4_K_M.gguf` | **۴٫۷ گیگ** | `data/models` | ⭐ پیشنهاد اصلی، فارسی خیلی بهتر، کاملاً روی ۸ گیگ VRAM |
| `Qwen2.5-14B-Instruct-Q4_K_M.gguf` | **۹٫۰ گیگ** | `data/models` | کیفیت بالا؛ نیمی از لایهها روی CPU میرود و کندتر است |
| `wikipedia_fa_top_mini_2026-07a.zim` | **۲۲۰ مگ** | `data/library/zim` | ویکیپدیای فارسی، فقط مقالههای برتر (شروع سریع) |
| `wikipedia_fa_all_mini_2026-10.zim` | **۲٫۶ گیگ** | `data/library/zim` | ⭐ همهٔ مقالههای فارسی، بدون عکسهای سنگین |
| `wikipedia_fa_top_maxi_2026-07a.zim` | **۲٫۴ گیگ** | `data/library/zim` | مقالههای برتر فارسی **همراه عکس** |
| `wikipedia_fa_all_nopic_2026-10.zim` | **۶٫۴ گیگ** | `data/library/zim` | همهٔ مقالهها، بدون عکس |
| `wikipedia_fa_all_maxi_2026-10.zim` | **۱۳٫۸ گیگ** | `data/library/zim` | ویکیپدیای فارسی کامل |
| `wikipedia_en_top_mini_2026-09.zim` | **۳۰۰ مگ** | `data/library/zim` | ویکیپدیای انگلیسی، مقالههای برتر |
| `wikipedia_en_top_maxi_2026-09.zim` | **۷٫۰ گیگ** | `data/library/zim` | نسخهٔ انگلیسی همراه عکس |
| نمونهٔ تست `samples/*.zim` | **۱۴ مگ** | همین مخزن | فقط برای اینکه سریع امتحان کنید |
| فونت وزیرمتن | ۲۵۰ کیلوبایت | `assets/fonts` | ✅ از قبل داخل برنامه هست |

**حداقل پیشنهادی برای شروع:** `llama-cuda` + `model-balanced` +
`zim-fa-mini` ≈ **۷٫۶ گیگ**. اگر فقط یک فلش ۴ گیگی دارید: مدل ۳B +
`zim-fa-top-mini` + `llama-cpu` ≈ **۲٫۲ گیگ**.

لینکها:
- مدلها: <https://huggingface.co/bartowski/Qwen2.5-7B-Instruct-GGUF>
  (اسم دقیق فایل تکفایلی `Qwen2.5-7B-Instruct-Q4_K_M.gguf`؛ نسخههای رسمی
  Qwen چندتکهاند، پس از مخزن bartowski استفاده کردم)
- ZIMها: <https://download.kiwix.org/zim/wikipedia/> (نام فایل شامل تاریخ است؛
  اگر عوض شده بود، جدیدترین `..._mini_...` را بردارید)
- llama.cpp: <https://github.com/ggml-org/llama.cpp/releases> → جدیدترین
  پیشانتشار `b####` → فایل `llama-b####-bin-win-cuda-12.4-x64.zip` (یا `cpu-x64`).
  نسخهٔ پینشده در اسکریپت: `b11901`.

### سیستم پیشنهاددهندهٔ مدل

تب «دستیار آفلاین» رم، تعداد هستهها و VRAM را میسنجد و پیشنهاد میدهد:

- رم کمتر از ۱۰ گیگ و بدون GPU → **3B** (حدود ۲ گیگ، روی CPU)
- رم ۱۶+ یا VRAM ۶+ گیگ → **7B Q4_K_M** (۴٫۷ گیگ)
- **سیستم شما (۳۲ گیگ DDR4 + ۸ گیگ VRAM)** → 7B بهصورت کامل روی GPU و
  سریع؛ 14B هم اجرا میشود ولی با CPU-offload کندتر است.
- اگر CPU و GPU ضعیف باشند، `-ngl 0` میشود (اجرای CPUای).

## ۵. وارد کردن از فلش یا هارد خارجی

دو راه دارید:

**راه ۱ — از داخل برنامه (پیشنهادی):**
- کتابخانهٔ آفلاین → «وارد کردن فایل ZIM» → فایل را انتخاب کنید → بپرسد
  «کپی به data» یا «فقط ثبت مسیر» (اگر فلش همیشه وصل نیست، حتماً کپی را بزنید).
- دستیار آفلاین → «وارد کردن مدل از فلش» و «وارد کردن llama-server».
- کتابخانهٔ آفلاین → «وارد کردن فایل از فلش» برای PDF/HTML/TXT/MD/DOCX.

**راه ۲ — با دستور (بدون باز کردن برنامه):**

```bat
python tools\prepare_downloads.py --import-folder D:\
```

این دستور `*.gguf` را به `data/models`، `*.zim` را به `data/library/zim`،
`llama-server.exe`/`*.dll` را به `data/bin`، و فایلهای متنی/PDF را به
`data/library/فایلهای من` کپی میکند. بعد برنامه را باز کنید و «اسکن پوشهٔ
کتابخانه» را بزنید.

> بعد از هر وارد کردن، حتماً **یکبار تست کنید** (مثلاً توی کتابخانه سرچ کنید
> «اینترنت»، و توی دستیار یک سؤال بپرسید).

## ۶. پنج مرحله — و نحوهٔ تست هر کدام

همهٔ مراحل در یک برنامه هستند؛ ولی با `--stage N` میتوانید فقط همان N مرحلهٔ
اول را ببینید و مرحلهبهمرحله تست کنید:

```bat
HamrahGhatie.exe --stage 1
HamrahGhatie.exe --stage 2
...
HamrahGhatie.exe --stage 5
```

همچنین `--demo` یک چرخهٔ مصنوعی (آزاد ← فقط ملی ← قطع کامل ← برگشت)
را **بدون هیچ درخواست شبکهای** شبیهسازی میکند تا اعلانها و تاریخچه را ببینید:

```bat
HamrahGhatie.exe --demo --stage 1
```

### مرحله ۱ — داشبورد وضعیت اتصال
هر ۱۰ ثانیه (قابل تنظیم) اینها **جداگانه** تست میشوند: سایتهای داخلی
(aparat، digikala، irna)، سایتهای خارجی (google، cloudflare)، اتصال TCP به
`1.1.1.1` / `8.8.8.8`، DNS سیستم و DNS خام UDP به `1.1.1.1`، مودم/روتر
(دروازهٔ پیشفرض) و وضعیت کارت شبکه. نتیجه: 🟢 آزاد / 🟡 فقط ملی /
🔴 قطع کامل. تغییر وضعیت با **هیسترزیس** (چند نمونهٔ پیاپی) تأیید میشود تا
اعلان دروغین ندهد. تاریخچهٔ قطعیها و نمودار ۲۴ ساعت در همان صفحه است؛
اعلان ویندوز هنگام تغییر، و اعلان ویژه + پیام «کارهای عقبافتاده» هنگام
**اولین برگشتن نت جهانی**.

**تست:** `--demo --stage 1` را ۴۰ ثانیه باز بگذارید؛ باید چهار وضعیت و یک
ردیف در «تاریخچهٔ قطعیها» ببینید.

### مرحله ۲ — کیف آمادگی
صف دانلود SQLite با فایل `*.part`، هدر `Range` و `If-Range`/ETag → اگر وسط
دانلود قطع شود، از همان بایت ادامه میدهد. ذخیرهٔ صفحهٔ وب بهصورت
`index.html` + پوشهٔ `assets` (عکسها، CSS، JS و حتی `url()` داخل CSS) با
بازنویسی لینکها. چکلیستی با ۱۸ قلم پیشفرض + افزودن/حذف/تیک دلخواه. در حالت
«فقط ملی» صف اتوماتیک متوقف میشود و با برگشتن نت آزاد ادامه میدهد.

**تست:** یک لینک فایل و یک لینک صفحه اضافه کنید؛ وسط دانلود کابل/وایفای را
قطع کنید (یا `--demo` بزنید)؛ بعد از برگشت، همان فایل ادامه پیدا میکند.

### مرحله ۳ — کتابخانهٔ آفلاین
خوانندهٔ **بومی ZIM** (نگارش ۵/۶، فشردهسازی zstd/xz/zlib/بدون فشردهسازی،
ریدایرکتها، namespaceهای قدیمی و جدید) داخل خود برنامه؛ نیازی به نصب Kiwix
نیست (در صورت وجود `libzim` بهعنوان پشتیبان استفاده میشود). جستجوی تماممتن
روی PDF، HTML ذخیرهشده، TXT/MD/DOCX/EPUB و مقالههای ZIM با **SQLite FTS5**؛
نرمالسازی فارسی یعنی `ی/ي`، `ک/ك`، نیمفاصله، اعراب، کشیده و ارقام
فارسی/عربی/لاتین همگی یکی حساب میشوند.

**تست:** فایل `samples/wikipedia_climate_change_mini.zim` را وارد کنید،
بعد سرچ کنید `climate` و `اقلیم`. همچنین یک فایل متنی با «اينترنت ملي»
بسازید و سرچ کنید «اینترنت ملی».

> نکته: برای ZIMهای خیلی بزرگ، پیشفرض ۵۰۰۰ مقاله ایندکس تماممتن میشود
> (قابل تغییر در `settings.json`)؛ جستجوی **عنوان** روی همهٔ مقالهها مستقیم
> از خود ZIM انجام میشود. نمایش مقالهها بهصورت متن ساده است، نه اجرای
> جاوااسکریپت/عکسهای ویکیپدیا.

### مرحله ۴ — دستیار هوش مصنوعی آفلاین
مدل GGUF را با `llama-server.exe` (llama.cpp) روی **همان کامپیوتر** اجرا
میکند. تنها ارتباط، loopback به `127.0.0.1` است (هدف `LOCAL_AI` در سیاست
شبکه؛ اتصال به هر آدرس غیر لوپبک مسدود است). پاسخها کلمهبهکلمه (SSE stream)
نمایش داده میشوند، تاریخچهٔ گفتگوها در SQLite ذخیره میشود، و optionally از
روی کتابخانهٔ آفلاین با **ذکر منبع** جواب میدهد.

**تست:** مدل و `llama-server.exe` را وارد کنید → «اجرای مدل» → بپرسید
«یه خلاصه دربارهٔ قطعی اینترنت بده». لاگ فنی مدل در `data/logs/llama.log`.

### مرحله ۵ — شبکهٔ محلی بدون اینترنت
چند کامپیوتر وصل به یک مودم/وایفای (حتی بدون اینترنت) از طریق UDP broadcast
**امضاشده با کد جفتسازی** همدیگر را پیدا میکنند. ارتباط TCP با تبادل کلید
X25519 + HKDF و **AES-256-GCM** رمز میشود؛ کلید ثابت هر دستگاه بعد از اولین
اتصال پین میشود. چت و ارسال فایل **بدون محدودیت حجم**، با فایل `*.part` و
ادامه از همان آفست بعد از قطع ارتباط. قبل از دریافت هر فایل حتماً یک دیالوگ
تأیید (نام + حجم + هش) نشان داده میشود. اگر broadcast مسدود بود، IP دستی
بزنید.

**تست:** برنامه را روی دو کامپیوتر با یک کد ۶رقمی اجرا کنید؛ باید همدیگر
را ببینند. پیام بفرستید و یک فایل بفرستید؛ وسطش یکی را ببندید و دوباره باز
کنید → فایل ادامه پیدا میکند.

<a id="offline-policy"></a>

## ۷. تضمین آفلاین و سیاست شبکه

تمام درخواستهای شبکهای از یک «نگهبان» (`hamrah/core/netpolicy.py`) رد
میشوند و باید یکی از این اهداف را داشته باشند:

| هدف | چه زمانی |
|---|---|
| `PROBE` | تستهای وضعیت اتصال (هر ۱۰ ثانیه) |
| `DOWNLOAD` / `PAGE_ASSET` | فقط دانلود/صفحهای که **خودتان** شروع کردهاید |
| `LOCAL_AI` | فقط `127.0.0.1` برای llama-server (هر مقصد دیگر مسدود است) |
| `LAN` | کشف و ارتباط با کامپیوترهای همان شبکهٔ محلی |

هیچ درخواست دیگری وجود ندارد. تستها همچنین سورسکد را اسکن میکنند تا
وابستهای مثل `requests`، `httpx`، CDN، Google Analytics یا Sentry وارد
نشود. کلاینت HTTP بهطور پیشفرض پروکسی سیستم را دور میزند تا تست وضعیت،
واقعیت اتصال را نشان دهد (در تنظیمات قابل تغییر است).

خطاها همیشه **فارسی و کاربرپسند** به کاربر نشان داده میشوند و متن فنی
کامل (traceback) در `data/logs/app.log` (چرخشی، ۲ مگ × ۳ نسخه) ذخیره میشود.

## ۹. عیبیابی

| مشکل | راهحل |
|---|---|
| اصلاً باز نمیشود / پنجره نمیآید | `data/logs/app.log` را باز کنید. اگر خطای `MSVCP140.dll` یا `VCRUNTIME` داد، «Visual C++ 2015-2022 Redistributable x64» مایکروسافت را نصب کنید. برنامه را داخل `Documents` یا فلش بریزید، نه `C:\Program Files`. |
| پیام «دسترسی به فایل ممکن نیست» | پوشه فقطخواندنی است. کل پوشه را جایی با دسترسی نوشتن کپی کنید (روی فلش هم خوب است، ولی مطمئن شوید قفل نباشد). |
| ویندوز هشدار SmartScreen میدهد | چون exe امضا نشده طبیعی است؛ «More info → Run anyway». بهتر است هش فایل را با نسخهای که خودتان ساختهای مقایسه کنید. |
| فونت فارسی بههمریخته / مربع مربع | `assets/fonts/Vazirmatn-Regular.ttf` و `-Bold.ttf` باید کنار بسته باشند. اگر پاک شدهاید، دوباره از مخزن بگیرید. Qt شکلدهی را خودش انجام میدهد. |
| وضعیت همیشه 🔴 است ولی نت دارم | تنظیمات → لیست «سایتهای داخلی/خارجی» را چک کنید؛ فایروال/آنتیویرویس را موقتاً غیرفعال کنید؛ اگر پشت پروکسی هستید «استفاده از پروکسی سیستم» را روشن کنید. لاگ `app.log` دلیل دقیق هر پروب را نشان میدهد. |
| اعلان ویندوز نمیآید | تنظیمات ویندوز → Notifications را روشن کنید، Focus Assist/Do not disturb خاموش باشد، آیکون سینی سیستم مخفی نباشد. اعلان درونبرنامهای همیشه کار میکند. |
| دانلود بعد از قطعی ادامه پیدا نمیکند | سرور مقصد باید `Range`/`206` بدهد؛ اگر `200` بدهد برنامه امنانه از اول مینویسد (پیامش در وضعیت آیتم است). فایل `*.part` را پاک نکنید. دکمهٔ «ادامهٔ صف» را بزنید. |
| صفحهٔ وب ذخیرهشده عکس ندارد | بعضی سایتها عکسها را با جاوااسکریپت lazy-load میکنند؛ صفحات ایستا بهترین نتیجه را میدهند. سقف پیشفرض ۱۵۰ فایل و ۸ مگ برای هر فایل است (در `settings.json` قابل تغییر). |
| ZIM باز نمیشود / «فایل ZIM معتبر نیست» | فایل ناقص دانلود شده؛ دوباره دانلود کنید (هش را چک کنید). اگر نسخهٔ خیلی جدیدی از ZIM است، `libzim` اختیاری را نصب کرده و دوباره بستهبندی کنید. لاگ `app.log` نوع فشردهسازی را مینویسد. |
| ایندکس ZIM خیلی طول میکشد | طبیعی است (چند گیگ). `zim_max_articles` را کم کنید یا از نسخهٔ `top_mini` استفاده کنید. عنوانها همیشه مستقیم از ZIM جستجو میشوند. |
| مدل اجرا نمیشود | `data/logs/llama.log` را ببینید. معمولاً `llama-server.exe` نیست، نسخهٔ cpu/cuda اشتباه است، یا مدل ناقص است. `llama_ctx` را به ۲۰۴۸ کاهش دهید یا مدل 3B را امتحان کنید. DLLهای همراہ بستهٔ cuda حتماً در `data/bin` باشند. |
| مدل انگلیسی/بیربط جواب میدهد | از مدل `*Instruct*` استفاده کنید، دمای پایینتر (۰٫۵) بگذارید، و سؤالتان را فارسی و واضح بپرسید. سیستمعامل prompt فارسی است. |
| دستگاهها همدیگر را پیدا نمیکنند | کد جفتسازی دقیقاً یکی باشد؛ هر دو روی یک subnet باشند؛ فایروال ویندوز پورتهای UDP/TCP تنظیمات را باز کند؛ «AP Isolation» مودم خاموش باشد؛ در نهایت IP دستی بزنید. |
| اتصال رد شد: «کلید دستگاه عوض شده» | یکی از طرفین `data` را پاک/ریست کرده. `data/peers.json` را خذف کنید تا دوباره جفت شوند. |
| فایل ناقص دریافت شد | هش SHA-256 چک میشود؛ اگر درست نباشد فایل `*.part` نگهداشته میشود و دفعهٔ بعد ادامه پیدا میکند (rename نمیشود). |
| دیتابیس قفل شده / خراب | برنامه را کامل ببندید، فایلهای `app.db-wal` و `app.db-shm` را پاک کنید، دوباره باز کنید. در بدترین حالت `app.db` را از پشتیبان برگردانید. |
| روی فلش کند است | فلشهای قدیمی برای SQLite/WAL کنداند؛ پوشه را روی هارد داخلی بگذارید و فقط مدل/ZIM را از فلش وارد کنید. |

## ۱۰. محدودیتها و نکات امنیتی (صادقانه)

1. **exe ویندوزی اینجا ساخته و تست نشد.** سورس، `build.bat`، فایل spec و
   workflow ویندوزی تحویل داده شده. حتماً یکبار روی ویندوز `build.bat` را
   اجرا کنید (تستها هم همانجا اجرا میشوند) و program را باز کنید.
2. **اعلان ویندوز** (`QSystemTrayIcon`) فقط روی ویندوز قابل تست است؛ در محیط
   offscreen من فقط اعلان درونبرنامهای و ثبت تاریخچه تست شد.
3. **مدل هوش مصنوعی واقعی تست نشد** (فایل GGUF چند گیگابایتی و GPU در محیط
   من نبود). استریم SSE، ساخت prompt، RAG و تاریخچه روی یک `llama-server`
   شبیهسازیشده روی `127.0.0.1` تست شد. قبل از قطعی حتماً یک چت واقعی امتحان کنید.
4. خوانندهٔ ZIM روی **یک فایل ZIM واقعی** (نسخهٔ ۵، کلاستر zstd، ۲۰٬۵۶۵
   ورودی) تست شد: متادیتا، صفحهٔ اصلی، ریدایرکت، جستجوی عنوان و ایندکس
   تماممتن. حالتهای نادر (کلاستر extended نسخهٔ ۶، LZMA، ZIM چندتکه) بر
   اساس مستندات openZIM پیادهمسازی شده ولی با فایل واقعی تست نشده. `libzim`
   بهعنوان پشتیبان پیشبینی شده است.
5. پروتکل رمزنگاری شبکهٔ محلی (X25519 + PSK + AES-GCM) **اختصاصی و
   حسابرسی نشده** است. برای شبکهٔ خانگی مناسب است؛ ادعای امنیت اثباتشده
   نمیکنیم. کد جفتسازی را مثل رمز نگهدارید.
6. نمایش مقالههای ZIM متن ساده است (بدون اجرای JS/قالب ویکیپدیا).
7. `--demo` فقط برای تست است و هیچ شبکهای باز نمیکند.
8. `libzim` اختیاری است و GPLv3 دارد؛ **بهصورت پیشفرض بستهبندی نمیشود**
   (خوانندهٔ بومی ZIM بدون آن کار میکند). اگر خواستید `build.bat
   --with-libzim` بزنید؛ حدود ۲۱ مگابایت اضافه میکند. برای انتشار عمومی به
   `LICENSE-THIRD-PARTY.md` نگاه کنید.

### خلاصهٔ آنچه **واقعاً تست شد** (در محیط لینوکس، ۵۵ تست pytest)

- ✅ تبدیل تاریخ شمسی (مقایسه با `jdatetime` روی ۴۰۰۰ تاریخ تصادفی: صفر اختلاف)
- ✅ نرمالسازی فارسی و جستجوی FTS5: «اينترنت ملي» = «اینترنت ملی»،
  «شبكه» = «شبکه»، نیمفاصله، اعراب، ارقام
- ✅ تشخیص سه وضعیت، هیسترزیس، باز/بسته شدن دورهٔ قطعی، اعلان برگشت نت
- ✅ اجرای واقعی پروبها روی اینترنت محیط تست (نتیجه: 🟢 آزاد، ۵/۵ خارجی)
- ✅ صف دانلود: ادامه از `Range`، fallback به ۲۰۰، توقف در حالت ملی،
  دانلود واقعی روی سرور HTTP محلی
- ✅ ذخیرهٔ صفحهٔ وب همراه عکس/CSS و بازنویسی لینکها (سرور HTTP محلی)
- ✅ خوانندهٔ ZIM روی فایل واقعی + ایندکس و جستجوی یکپارچه
- ✅ رمزنگاری و تبادل کلید، کشف امضاشده، تأیید دریافت فایل، ادامهٔ انتقال
- ✅ **انتقال فایل و پیام واقعی بین دو گره روی TCP loopback** با بررسی هش
- ✅ استریم SSE مدل، تاریخچهٔ چت، پیشنهاد مدل بر اساس سختافزار
- ✅ سیاست شبکه: جلوگیری از خروج مدل به غیر لوپبک، اسکن سورس برای CDN/تلهٔمتری
- ✅ رابط کاربری PySide6 با `--stage 1..5` بهصورت offscreen، و چرخهٔ کامل
  `--demo` (آزاد → ملی → قطع → برگشت) همراه ثبت تاریخچه در SQLite
- ✅ **بستهبندی PyInstaller واقعاً اجرا شد** (روی لینوکس) و فایل اجرایی
  frozen حاصل هم اجرا شد: فونت وزیرمتن داخل `_internal/assets/fonts` باندل
  شد و پوشهٔ `data` درست کنار exe ساخته شد. حجم: ۲۵۱ مگابایت.
  (همین spec و وابستگیها روی ویندوز توسط `build.bat`/CI ساخته میشوند.)

**تست نشد:** exe ویندوزی، اعلان سینی ویندوز، مدل GGUF واقعی/GPU، فونت از
نظر بصری، و تشخیص دروازه توسط PowerShell روی ویندوز واقعی.
